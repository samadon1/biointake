# Research: how existing LIMS present receiving, and what that means for us

Run 2026-08-27 across OpenSpecimen, BSI (Biological Specimen Inventory), Freezerworks, LabVantage, LabWare,
Sapio, SLIMS, STARLIMS, SampleManager, Nautilus, MISO. Flags preserved from the researcher.

## The finding that reframes the brief

The only published usability study of laboratory information systems (Mathews & Marc, *J Pathol Inform* 2017;8:40)
ranks tasks by user-reported difficulty across US hospital LIS users:

- **Easiest**: accessing a patient record (40.3%), printing labels (37.9%), **receiving a specimen (34.7%)**
- **Hardest**: ad-hoc management reports (21.3%), copying results to recipients (10.3%), QC reports (9.0%)
- Overall **SUS = 59.7**, significantly below the 68 benchmark (p < 0.001)

**Receiving is among the three best-rated tasks in the incumbents.** The recurring complaints, "slow", "too many
clicks", "difficult", "cumbersome", land on reporting and getting data *out*, not on intake.

> "LabVantage is a data black hole. You can put data in but you must spend a LOT of time deciphering the tables,
> columns, and application architecture … to have any hope of getting your data back out.", Capterra, 2019

**Consequence for BioIntake:** we do not win by making a prettier receive screen. Receiving is table stakes.
Our differentiator is the part no incumbent does, **the agent performing the reconciliation and the chasing,
and the case being answerable afterwards**. The UI's job is to make that legible, not to out-form a form.

## Patterns worth stealing

1. **The manifest defines the rows; the scanner fills one column.** Nautilus pre-generates one row per expected
   tube from the kit layout, so the operator only tabs down the Barcode column, **discrepancy detection becomes
   free**. Converges with MISO's `emptyPositions`: constrain the input surface so errors are unrepresentable.
2. **The staging batch.** BSI never writes to inventory directly: everything lands in a batch with **blue cells =
   warnings, red = errors** inline, and must be explicitly committed, optionally double-keyed.
3. **Status gates location.** SLIMS, verbatim: *"If the status is not pending, removed, or cancelled, the location
   will also be required."* Better than unconditionally mandatory or unconditionally optional.
4. **Scan mapping as configuration.** BSI: number of barcodes, a field mapping per barcode, and a per-barcode
   action of **Match / Replace / Time Stamp**; plus **Append Unmatched Rows** and named Translation Schemas.
5. **Auto-allocation takes constraints, not "next free".** LabWare: *"free, contiguous storage space for 4
   specimens requiring storage at −20 °C"*. BSI supplies Pattern (Across | Serpentine), Orientation, and a start
   row/column for backfilling partly-full boxes.

## Discrepancies are a first-class module, not a validation message

BSI: **Add / Edit / Resolve / Delete Discrepancy**, plus **Mark All as Irresolvable**; states
**Unresolved / Resolved / Irresolvable**; unresolved fields shade red; BSI **auto-creates a Status discrepancy for
any manifest specimen never received**; the Shipment Manager list carries **Discrepancy Count** and
**Discrepant Specimens** as columns.

> `Irresolvable` is the state we lack. Real receiving generates discrepancies nobody will ever close, and forcing
> them to stay "open" forever poisons the queue. (It rhymes with the EDC model's `Cancelled`.)

BSI's vial status enum is richer than ours: `In · Out · Reserved · Lost/Missing · Destroyed/Broken · Empty ·
On Hold · Discrepant · Pre BSI2 · Array Core · Blinded`, note **On Hold** and **Discrepant** as distinct states.

## Field-table observations

**BSI "Shipment Received" dialog**, the cleanest receive header found, two columns:
Received By · Date Shipped · Received Package Count · Est. Specimens Received | Condition (default *Acceptable*) ·
Date Received · Expected Completion Date · **Reason Unacceptable (disabled until Condition = Unacceptable)**.
Note the **conditional enable**, the reason field is inert until needed rather than always-present-and-blank.

**Sapio** models receipt as its own entity `SampleReceipt` with `Received | Rejected` and a rejection-reason enum
(`Container Compromised · Failed Temperature Strip Reading · No Sample`); its `Request` carries
**`Partially Received`** with a dedicated `PartiallyReceivedDate`, partial shipments modelled explicitly,
which nothing else surveyed does.

**LabVantage Quick Login requires nothing**: *"The default configuration does not require any fields to be
completed at this time… A unique sample identifier will be generated by the system."* Receiving is a separate
state transition with a **Receive and Assign Storage** button.

## Theme: universally light
No confirmed dark mode in any commercial product surveyed (one LabVantage "Stellar" portal element adapts).
Freezerworks is a 4D desktop app descending from Freezerworks for DOS (1992), minimum resolution 1280×1024.

## Unverified
SampleManager and STARLIMS login field names · LabWare's classic Sample Login field list · BSI's e-signature
dialog · Sapio and SLIMS screenshots (CDN 403s, descriptions rest on text claims) · 2D rack readers
(Ziath/FluidX/Micronic) for every commercial product: the architecture everywhere is decoder-writes-CSV →
LIMS-ingests-file, not live drivers · **no published time-per-sample accessioning benchmark exists**.
